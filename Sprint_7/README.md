#SPRINT_7 FINAL TEST#

##Данный проект представляет собой набор модулей для автоматического тестирования API веб сайта https://qa-scooter.education-services.ru/##

Проект содержит в себе файлы  .gitignore, data.py, helpers.py, main.py, README.md, urls.py, и директории:<br> 

tests - с тестами и фикстурами conftest.py,<br>
allure_results - результаты прохождения тестов allure,<br>
allure_report - отчёт о прохождении тестов allure, открывается из командной строки командой - allure open allure_report<br>
<br>

##Описание файлов##<br>
<br>
*.gitignore -  названия всех файлов и папок, которые не нужно коммитить<br>
<br>

* helpers.py - в файле описан класс Helper с вспомогательными методами для генерации тестовых данных с помощью модулей string и random<br>
<br>
* api_methods.py - в файле представлены методы запросов к ручкам https://qa-scooter.education-services.ru/
<br>
*  data.py - в файл вынесены данные о номерах станций метро для создания рандомного заказа<br>
<br>
* urls.py - в файл вынесены ссылки на тестируемые страницы <br>
<br>


##Описание директорий##<br>
###tests###<br>
Cодержит файлы conftest.py с фикстурами и 6 файлов с тестами разных функциональностей , каждый со своим тестовым классом и тестами :<br>

--conftest.py - фикстуры создающие и удаляющие данные о курьере <br>

--test_accept_order_api.py - проверки принятия курьером созданного заказа: 1 позитивный и 4 негативных сценария:
успешный запрос возвращает{"ok":true};
если не передать id курьера, запрос вернёт ошибку;
если передать неверный id курьера, запрос вернёт ошибку;
если не передать id заказа, запрос вернёт ошибку;
если передать неверный id заказа, запрос вернёт ошибку.<br>

--test_create_courier_api.py - проверки создание курьера:1 позитивный и 3 негативныхсценария: курьера можно создать;
нельзя создать двух одинаковых курьеров;
чтобы создать курьера, нужно передать в ручку все обязательные поля;
запрос возвращает правильный код ответа;
успешный запрос возвращает {"ok":true};
если одного из полей нет, запрос возвращает ошибку;
если создать пользователя с логином, который уже есть, возвращается ошибка.<br>

--test_delete_courier_api.py - проверки удаления курьера: 1 негативная и 1 позитивная: существующего и несуществующего курьера<br>

--test_get_order_api.py - возвращения созданного заказа и наличия в заказе обязательных полей: 1 позитивная и 2 негативные. Сценарии:
успешный запрос возвращает объект с заказом;
запрос без номера заказа возвращает ошибку;
запрос с несуществующим заказом возвращает ошибку. <br>

--test_login_courier_api.py -проверки логина курьера:1 позитивная и 4 негативные. Сценарии:
курьер может авторизоваться;
для авторизации нужно передать все обязательные поля;
система вернёт ошибку, если неправильно указать логин или пароль;
если какого-то поля нет, запрос возвращает ошибку;
если авторизоваться под несуществующим пользователем, запрос возвращает ошибку;
успешный запрос возвращает id<br>


--test_order_api.py - проверки создания и получения заказов. Сценарии:
можно указать один из цветов — BLACK или GREY;
можно указать оба цвета;
можно совсем не указывать цвет;
тело ответа содержит track.
Проверь, что в тело ответа возвращается список заказов.
<br>
